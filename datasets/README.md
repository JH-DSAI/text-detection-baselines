# Datasets

This directory holds prepared dataset files. **It ships empty**: no corpus of
third-party text is redistributed with this repository.

Two datasets are registered.

| name | default | data source | licence |
| --- | --- | --- | --- |
| `demo` | yes | Synthetic, generated by [`tools/make_demo_dataset.py`](../tools/make_demo_dataset.py) and bundled inside the package | BSD-3-Clause, same as this repository |
| `gede` | no | The GEDE corpus, obtained and prepared by you (below) | CC BY-NC-SA 4.0, plus the terms of three source corpora |

---

## `demo` — synthetic, bundled

`demo` is 200 records of machine-composed text with no third-party content, living
at `text_detection_baselines/datasets/data/demo.jsonl` so that it resolves
identically from a source checkout and from an installed wheel. It exists so that
`pixi run main` works with no data acquisition, and so the test suite has a dataset
whose properties are known exactly.

It carries **no detection signal of research interest.** The two classes are
separated by deliberately planted surface statistics — machine texts are more
repetitive, use longer words, and carry less punctuation — because the registered
models score exactly those features. Any number `demo` produces describes the
pipeline, not detection. Its composition:

| `contribution_level` | n | n_human | n_machine |
| --- | --- | --- | --- |
| Human | 60 | 60 | 0 |
| Mixed | 50 | 25 | 25 |
| Summary | 45 | 0 | 45 |
| Task | 45 | 0 | 45 |

Chosen so the suite exercises both slice shapes: `Human`, `Task`, and `Summary` are
single-label, where ranking metrics are undefined, and `Mixed` has both classes,
where they are defined. Eight records inside `Mixed` are short enough to be flagged
out-of-distribution, so OOD restriction runs on a real evaluation rather than only
in unit tests. Responses are capped at 55 tokens; the cap is not cosmetic, and the
reasoning is documented at `MAX_TOKENS` in the generator.

Regenerate with:

```bash
pixi run make-demo-dataset
```

The generator is seeded, so this is reproducible: regenerating without changing the
generator leaves the file byte-identical.

## `gede` — obtained and prepared by you

GEDE (Generative Essay Detection in Education) accompanies the paper [*Assessing LLM
Text Detection in Educational Contexts: Does Human Contribution Affect Detection?*](https://arxiv.org/abs/2508.08096)
and the dataset code is published at [`lukasgehring/Assessing-LLM-Text-Detection-in-Educational-Contexts`](https://github.com/lukasgehring/Assessing-LLM-Text-Detection-in-Educational-Contexts).

### Licence and why it is not bundled

The GEDE data is licensed **CC BY-NC-SA 4.0**
(<https://creativecommons.org/licenses/by-nc-sa/4.0/deed.en>): attribution required,
**non-commercial use only**, share-alike on derivatives. This repository is
BSD-3-Clause, and shipping the corpus inside it would both misstate the corpus's
licence and impose a non-commercial restriction on everything downstream.

GEDE is additionally derived from three corpora of student academic writing that
retain their own terms, all of which apply on top of the CC BY-NC-SA licence:

| source corpus | records in GEDE | notes |
| --- | --- | --- |
| BAWE (British Academic Written English) | 6,531 | Distributed under its own licence terms |
| Argument Annotated Essays (TU Darmstadt) | 5,938 | Not included in the upstream database; added by upstream's own script |
| PERSUADE 2.0 | 1,150 | Distributed under its own licence terms |

916 of the records are human-written student essays rather than model output, so
this is third-party human-subject text. **Obtaining the corpus is therefore your
step, not ours** — that keeps acceptance of every one of these terms with the
person who agrees to them.

Cite GEDE *and* all three source corpora in any work using it. Consult the upstream
repository for the current citations; it also carries the paper appendix.

### Acquisition

1. Initialize submodules, cloning a fork of the GEDE repository—in doing so, accepting the terms above: `git submodule update --init`
2. cd to the cloned fork: `cd Assessing-LLM-Text-Detection-in-Educational-Contexts`
3. Unpack `database/database.db.zip` to `database/database.db`: `unzip database/database.db.zip`
4. Download [the AAE dataset](https://tudatalib.ulb.tu-darmstadt.de/items/9177c48c-8bd5-4881-9cb4-0632b5941464) to `ArgumentAnnotatedEssays-2.0.zip`.
5. Add the AAE essays to the database: `pixi x --spec pandas python database/add_aae_to_database.py`
   The published database ships with the Argument Annotated Essays texts blank, and
   the script fills them in by downloading the corpus from TU Darmstadt. Skipping it
   leaves 5,938 records with empty text.
6. cd back to this repository and convert the database into a file this package can load: `cd .. && pixi run prepare-gede --source Assessing-LLM-Text-Detection-in-Educational-Contexts/database.db`

With no `--out`, this writes `datasets/gede_essays.jsonl` in a source checkout, or
`${XDG_CACHE_HOME:-~/.cache}/text-detection-baselines/gede_essays.jsonl` otherwise.
Set `TDB_GEDE_PATH` to override both the write location and where the `gede` dataset
is looked up. The prepared file and its sidecar are git-ignored.

Then:

```bash
pixi run main -- --dataset gede
```

If `gede` has not been prepared, `--help` marks it `(not prepared)` and selecting it
fails with the command above rather than a missing-file traceback.

**Note:**  This script applies hard-coded overrides to patch a few idiosyncrasies in the dataset:

- Max tokens for dipper (n/a → 512)
- Temperature for dipper (n/a → 1)
- Question text for questions 276, 284, 286, 304 (empty → original question text)

### What the converter does

[`text_detection_baselines/datasets/gede.py`](../text_detection_baselines/datasets/gede.py)
reads the SQLite database directly using only the standard library, and emits JSONL
whose keys match this package's defaults (`answer`, `label`, `contribution_level`),
so no key overrides are needed.

It reads the database rather than the CSV that upstream's
`database/export_to_csv.py` produces, because that export drops the `is_human`
column — so `essays.csv` **has no label column at all** and cannot be loaded here —
and also omits the question text and the generation parameters. Passing a `.csv` or
a `.zip` to `--source` produces an error saying so.

Two behaviours are worth knowing about:

* **Empty text is fatal by default.** If any record has a blank `answer` — the
  signature of a skipped step 3 — the converter refuses to write, and names the
  affected corpora. Loading those records would score empty strings as real samples
  and silently corrupt every metric. `--allow-missing-aae` drops and counts them
  instead, yielding a deliberately incomplete corpus.
* **`contribution_level` normalization mirrors upstream** (`improve-human` →
  `Improved-Human`, `rewrite-N` → `Rewrite-LLM`, `dipper-N` → `Humanize`, and so
  on). Values upstream does not map — `task+resource` is one in the published
  corpus, hence its inconsistent casing — pass through unchanged and are reported
  rather than silently absorbed.

Every run writes a `<output>.meta.json` sidecar recording the source SHA-256, the
adapter version, a UTC timestamp, and the full composition, so a prepared file can
be traced to what produced it.

### Composition of the published corpus

Recorded here because these three facts are needed before any `gede` number can be
read correctly, and because the metric caveats in the top-level
[README](../README.md) refer to them.

* **13,619 records: 916 human, 12,703 machine (93.27% machine).** Average precision
  is floored by prevalence, so AP above 0.93 on `gede` means nothing on its own.
* **Eight of the nine categories contain only machine samples**, so per-category
  ranking metrics are undefined (`-`) on almost every row.
* **`task+resource` has 40 samples** and renders at the same precision as categories
  45× larger.

| `contribution_level` | n | n_human | n_machine |
| --- | --- | --- | --- |
| Human | 916 | 916 | 0 |
| Humanize | 1,783 | 0 | 1,783 |
| Improved-Human | 1,832 | 0 | 1,832 |
| Rewrite-Human | 1,832 | 0 | 1,832 |
| Rewrite-LLM | 1,832 | 0 | 1,832 |
| Summary | 1,776 | 0 | 1,776 |
| Task | 1,832 | 0 | 1,832 |
| Task+Summary | 1,776 | 0 | 1,776 |
| task+resource | 40 | 0 | 40 |

Machine text was generated by `meta-llama/Llama-3.3-70B-Instruct` (5,460 records),
`gpt-4o-mini-2024-07-18` (5,460), and `dipper` (1,783), at `temperature = 1` and
`max_tokens = 512`.

## Using your own data

Any JSON array or JSON-lines file with a text field, a label field, and an optional
category field works:

```bash
pixi run main -- --register-file-dataset mydata=/path/to/mydata.jsonl
```

Labels may be `0`/`1`, `human`/`machine`, `real`/`fake`, `organic`/`generated`, or
booleans.

Field names must currently be `answer`, `label`, and `contribution_level`. The
`--text-key`, `--label-key`, and `--category-key` flags exist but do not yet take
effect (tracked as R3 in [REVIEW.md](../REVIEW.md)), so rename the fields in your
file for now rather than passing those flags.
